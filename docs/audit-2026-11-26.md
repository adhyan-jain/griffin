# Independent audit and repair of the research engine — 2026-11-26

This audit covers commits `44f3b34` (research engine, knowledge graph, playbooks, Research/Companies/Alumni pages), `7764f36` (application packages) and `0f5e20b` (eval/benchmark). The changes are uncommitted on `master`: 56 files modified, 28 new, +5.9k/−2.0k lines, and migrations 000024 and 000025.

## A. Independent assessment

**Correct as written, and kept**
- `web.NewFetcher` is SSRF-safe. It checks the IP at dial time, so DNS rebinding is covered. It also revalidates redirects and caps size, time and content type.
- RLS with `user_id` scoping is applied on all new tables and queries.
- Scoring in `internal/assess` has separate dimensions, and eligibility is separate from quality. Bare "Remote" is treated as unknown, not worldwide.
- The `internal/sources/ats` adapters are correct, including Ashby's `{"jobs":[...]}` shape.
- Application packages stay behind approval, and cover letters are fact-checked.
- Two earlier problems were already fixed: hardcoded "verified" listings (removed in `e0baa8a`) and the ₹10k stipend floor.

**Wrong or missing**
- The "iterative research engine" ran a single pass. Follow-up pages were fetched but never read, and two of the four budgets were never enforced.
- Runs ran in a goroutine started from an HTTP handler, with RLS bypassed. The API runs on Lambda, so in production those runs would never have executed.
- Every model-extracted claim was stored as `supported`, and its quote was never checked against the page.
- The query-dedupe map was process-global and shared across users. It also had a data race.
- Pause was overwritten by the run's final `COMPLETED` write, and there was no way to cancel.
- The playbooks were dead code. The Companies and Alumni pages read entities that nothing ever wrote, so they were always empty.
- Alumni outreach failed on every call: the approval had no `task_id`, which is NOT NULL. There was no do-not-contact handling anywhere.
- The alumni playbook gave every person a hardcoded graduation year of 2020 and a location of India. The companies playbook set `PayPotential: "high"` from keywords.
- The prompt-injection fence could be closed by page text, and synthesis input was not fenced.
- The frontend sent fields the backend doesn't read (`questions`, `general_research`) and read fields the backend doesn't return (`started_at`, `quote`).

**Overbuilt or coupled**
- A second store for companies (`canonical_entities` with kind=company) duplicated the existing `companies` table.
- Domain wording sat inside the core engine: careers, funding, tech stack.

## C. Architecture assessment

There is now one generic engine (`internal/research`) that runs with no playbook. A new playbook implements the `playbooks.Playbook` interface and is added to `playbooks.Registry`. It supplies default questions, plan guidance, query templates and a `ProcessResults` hook, which receives supported findings only. Core execution doesn't change. Persistence goes through Griffin's existing task engine and code-only-routine path; no new scheduler was added.

## F. Known limitations

- Research advances only while a host or the cloud worker is claiming tasks, which is the existing architecture.
- The time budget counts time spent inside steps, not wall-clock time.
- A crash between the evidence write and the run write can drop a finding's link to its question; the next gap check re-links it.
- A conflict's two sides are listed only in the final report, not while the run is in progress.
- Tracker rows without a LinkedIn URL are skipped on import. Nothing fills the per-person `country` except research.
- Your profile has no name or college fields, so outreach drafts use placeholders.
- `sites.go`, `community.go` and `hackathons.go` still use plain HTTP clients. They only call fixed public hosts. The SearXNG client stays plain on purpose, because it points at your own instance, usually on localhost.
- Scoring has no scam or fee signal, and `strongEngineeringEmployers` is hand-curated.
- Next.js printed a security-upgrade advisory (`next upgrade --agent=security`). It has not been run.

## H. Recommendation

The backend is now safe to use for real research. Claims are only marked supported when the quote is on the page, runs are durable and bounded, user data is isolated, and nothing is sent without your approval and a do-not-contact check. It is **not yet proven live**. Every test used fake search, fetch and LLM, and no page was exercised in a browser. Do item G1 before relying on the results.
